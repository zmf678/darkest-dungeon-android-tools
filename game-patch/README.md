# 《暗黑地牢》自动存档实验版

实验版以本机 Wicked Android 2.2.2 APK 为输入，通过独立包名安装。游戏完成存档提交及临时文件收尾后，补丁同步捕获发生变化的完整档位，使用原始文件字节生成 ZIP，通过签名保护的本机接口让档案馆直接显示版本。

## 安装与迁移

1. 安装游戏实验版 `dev.torcharchive.ddgame`，再安装同一证书签名的余烬档案馆实验版 `dev.torcharchive.dd.lab`。两个实验包可以与已有游戏及档案馆并行安装。
2. 如需迁移，在原版选择 **存档与模组 → 存档 → 导出**。在实验版选择 **存档 → 导入**，使用该导出副本。验收时优先使用新建测试档位。
3. 此后在实验版正常游玩。打开档案馆实验版，查看版本历史中的自动存档和当前状态。
4. 回档时选择一个自动版本并确认，完全退出实验版游戏后重新打开。游戏在加载存档前恢复该档位，并先把当时的进度存入历史。档案馆收到结果后显示游戏已确认回档。

实验版模组目录为 `Android/media/dev.torcharchive.ddgame/mods`。可通过实验版游戏的模组菜单导入原模组 ZIP，或在档案馆模组页连接对应目录。启用和加载顺序随档位文件保留，使用真实模组的档位仍需真机核对。

## 本地复现

在 Windows 上进入 `game-patch` 目录并运行 `python build.py --help` 查看参数。脚本核对源 APK 的 SHA-256，使用 JDK 21、Android SDK 36、Build Tools 36、NDK r28 和 Apktool 3.0.3 构建，输出改用独立包名、已对齐和已签名的本地实验 APK。APK 内的游戏资源和现有原生库来自用户提供的输入。暂存空间约需 12 GB。签名参数可通过环境变量或文件提供。

在档案馆项目根目录运行 `gradle -ParchiveLab=true :app:assembleDebug :app:lintDebug` 构建并行安装版。两份实验 APK 须使用相同证书。已有档案馆若要原地更新，需要用原分发证书对默认包名构建签名。

## 验证

- 主机测试通过了三次紧邻提交、重复捕获抑制、重新打开历史、多文件逐字节恢复、回档前版本保留、拒绝已损坏版本，以及还原被中断的替换。测试入口为 `test/dev/torcharchive/game/SnapshotStoreCheck.java`。
- APK 构建包含包签名和 ZIP 对齐校验。档案馆执行 Gradle 构建及 Android lint。
- Redmi K Pad 上的档案馆显示了 14 个真实游玩产生的版本，其中两次游戏存档提交相隔约 160 毫秒。
- 测试设备的 HyperOS 在通过游戏菜单完全退出后会阻止档案馆访问游戏接口。重新打开实验版游戏再切换到档案馆，即可读取版本历史。
- 仍需用测试档位在真机核对回档，以及带模组档位的启用和加载顺序。
